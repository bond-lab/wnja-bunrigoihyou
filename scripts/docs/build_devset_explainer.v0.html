Background

The project maps senses of the Japanese WordNet (wnja 2.1) to records of the 分類語彙表 (Word List by Semantic Principles, WLSP), NINJAL's thesaurus. To train and test that mapping we need a few hundred pairs that are known to be right: a dev set. This script builds it by composing two resources that already agree on a key.

WLSP: a record is a sense of a headword

bunruidb.txt has 101,067 records. Each is one headword at one position in the thesaurus, so the same word listed under two meanings is two records. wlsp.py reads a record into a WlspEntry (wlsp.py:150–178). Three real records that the dev set uses:

The code 2.3520-01-01-02 is 分類番号 (類.部門中項目分類項目), 段落, 小段落 and 語番号 joined by hyphens (WlspEntry.code, wlsp.py:66–69); its first digit is the 類: 1 体 (nouns), 2 用 (verbs), 3 相 (adjectives and adverbs), 4 其他. The lemma is the 見出し本体 with reading hints and usage notes stripped by normalise_midashi (wlsp.py:102–111): 時（とき） becomes 時, 浴びる［一風呂〜］ becomes 浴びる, は（穿）く［ズボンを〜］ becomes はく. 135 of the 734 dev rows have a 見出し that differs from its lemma this way. Record types: A is a plain headword, B a headword with several spellings or readings, and 1, 2, … its children. Of the 503 dev records, 484 are A, 10 are B, 6 are 1 and 3 are 2, so 会う above is a child record (type 1) of 見出し番号 80089.

TUFS: a basic vocabulary keyed by WLSP record

The TUFS basic vocabulary (Bond et al. 2020) is a multilingual word list whose concept ID cid is the WLSP record ID, without the zero padding. tufs-vocab.tsv (16,935 rows after the header) has one row per language per concept. For cid 84044 it has 26 rows; the two the script reads are

$ grep -P '^84044\t(ja|en)\t' ../tufs/tufs-vocab.tsv | cut -f1-5
84044	en	742	meet	会う
84044	ja	903	会います	【よみ】; あいます;【意味】; meet

Three things to notice. The Japanese lemma is the polite ます form 会います, while WLSP has the dictionary form 会う. The reading sits inside the comment after 【よみ】. And the English row's comment is just the Japanese gloss. Rows with cid None (1,213 of them) are words with no WLSP record and are skipped. Reading the file gives 850 concepts with an English or Japanese row; 799 have a Japanese row.

Some TUFS Japanese forms carry a disambiguation index or several variants: 入れます(2) "put", 切ります(2) "cut", あの(1) "that", よく(1) "often", ～語 "word". The index tells TUFS entries apart; it is not part of the word.

tufs-omw-map: concept to Princeton synset

tufs-omw-map.tsv links 503 concepts to 734 WordNet 3.0 synsets with a relation. It is three columns and no header:

$ grep -P '^(84044|9206|30521)\t' ../tufs/tufs-omw-map.tsv
9206	hyponym	15209413-n
30521	multi	06286395-n
84044	synonym	01470670-v
84044	synonym	02428924-v
$ cut -f2 ../tufs/tufs-omw-map.tsv | sort | uniq -c
     11 hyponym
      2 multi
    721 synonym

synonym says the WLSP record and the synset mean the same thing; hyponym says the record is narrower (来月 "next month" under month 15209413-n, 交番 "police box" under police station); multi marks a multiword or affix item (～語, あの(2) "Excuse me."). A concept can link to several synsets: 会う has two, and いい "good" (cid 91633) has twelve, one per sense of good. That is why 503 records give 734 rows.

The wordnets, through the wn library

Three lexicons sit in the project-local database .wn_data/: wnja:2.1, tufs-ja:2026.04.06 and omw-en:1.4. A wnja synset ID is the Princeton offset with a prefix, so 00604617-a is wnja-00604617-a. Each sense belongs to a word that lists a lemma and extra forms, which in wnja are the katakana and hiragana readings:

The sense ID wnja-00604617-a-12574 is what the dev set wants: it names 便利 in exactly this synset. Not every wnja word has readings: wnja-90000500-n lists 一昨年 with forms ['一昨年'] only, and not every Princeton synset has Japanese members at all (wnja-13836136-n, west, does not exist). The TUFS Japanese wordnet tufs-ja was built from the same vocabulary, so it has one sense per linked Japanese lemma, named after the lemma: tufs-ja-会います-02428924-v, tufs-ja-西-13836136-n, tufs-ja-便利-00604617-a.

Verbs are keyed by the dictionary form. The dev set's lemma column is always the WLSP 見出し本体 (会う, 入れる, 架ける), because that is what wnja lists too. The TUFS polite form is kept beside it in its own polite column (会います, 入れます, かけます) so that the TUFS wordnet, whose sense IDs contain the polite form, can still be joined. 88 of the 734 rows have a polite form; all 88 are 類 2 (用) records.

2 · TufsEntry and polite_form

build_devset.py:36–63

A TUFS concept is reduced to four strings: cid, Japanese lemma, yomi, english. polite_form decides whether the TUFS string is a ます verb worth keeping in the polite column. It takes the first ;-separated variant, strips a trailing (2)-style index, and keeps the result only if it ends in ます:

_INDEX = re.compile(r"\(\d+\)$")

def polite_form(tufs_form: str) -> str:
    form = _INDEX.sub("", tufs_form.split(";")[0].strip())
    return form if form.endswith("ます") else ""

3 · read_tufs: Japanese and English rows by concept

build_devset.py:66–96

One pass over tufs-vocab.tsv. Rows with cid None are skipped (lines 87–88); English rows fill english[cid], Japanese rows fill japanese[cid] with the lemma and the reading pulled from the comment by _yomi_from_comment:

m = re.search(r"【よみ】;\s*([^;【]+)", comment)
return m.group(1).strip() if m else ""

On '【よみ】; あいます;【意味】; meet' this returns あいます. The two dicts are merged over the union of their keys (lines 93–96), so a concept with only an English row, such as 7449 time, gets TufsEntry('7449', '', '', 'time'). 850 entries come out; 57 of the 503 linked concepts have an empty Japanese lemma.

4 · read_omw_map: synset links by concept

5 · find_sense: which sense in the synset?

build_devset.py:115–134

Given a wnja synset and the ordered candidate strings, compare each candidate with every sense's lemma and forms. The hiragana candidate is also tried in katakana, because wnja forms carry both:

for method, cand in candidates:
    if not cand:
        continue
    for sense in senses:
        word = sense.word()
        forms = {word.lemma(), *word.forms()}
        if cand in forms or hira_to_kata(cand) in forms:
            return sense.id, word.lemma(), method
return "", "", ""

For 架ける (cid 69867, synset 02741003-v) the members are 掛ける with forms ['掛ける', 'カケル', '懸ける', 'かける'] and 下げる. 架ける misses, かけます misses, かける hits, so the row gets wnja-02741003-v-5881, wnja_lemma 掛ける, match wlsp_yomi. The candidate order matters: the WLSP lemma is tried before the reading so that 伯母・叔母 cannot be claimed by a reading when a spelling is present. In this build the second and fourth candidates (tufs_lemma, tufs_yomi) never produced a match: the TUFS lemma is either the WLSP lemma already or a ます form wnja does not list.

7 · tufs_sense_id: the same lookup in the TUFS wordnet

build_devset.py:157–178

The TUFS Japanese wordnet names its synsets tufs-ja-{pwn} and has one sense per Japanese lemma, so the lookup is simpler: open the synset, return the sense whose word lemma is one of the ;-separated TUFS variants. The TUFS lemma here is the raw string, polite form and all, because that is what the TUFS wordnet was built from: tufs-ja-会います-02428924-v. With no TUFS wordnet (--tufs-lexicon '') or no Japanese lemma it returns "".

How much to trust this

This page was written by an AI from the source file. That makes it quick to produce and easy to refine, and fallible. A model can misread a line, invent a plausible detail, or keep a number that has since changed.

  • Every code claim carries a file:line reference into scripts/build_devset.py or scripts/wlsp.py at commit b3e6896. Open it and check.
  • The counts (734 rows, 503 records, 599 / 97 / 27 / 11, 648 and 26, 343, 88, 135) come from the committed dev/devset.tsv and the inputs in ../tufs as they were on 2026-11-05. Rerunning the script that day produced an identical file. Change wnja, the TUFS map or the WLSP release and the numbers move.
  • Every example word on this page (便利, 会う, 伯母・叔母, おととし, 西, 来月, 暑い, 架ける, …) is a real row, and the synset members shown were read from wnja:2.1 in .wn_data. The query blocks with a coloured left edge re-run them; they use polars and wn, so the mechanical checker skips them like output.
  • Statements about what never happens in this build (no tufs_lemma or tufs_yomi match; no ; in a Japanese TUFS form) are observations about these inputs, not guarantees of the code.
  • The quiz answers follow from the code; where one disagrees with the code, the code wins. Please report it.
  • The surest check is to run the script into a scratch path and diff the result against dev/devset.tsv.

Glossary

TermWhat it means here
WLSP / 分類語彙表NINJAL's thesaurus of Japanese, 101,067 records in bunruidb.txt. A record is one headword at one position, hence one sense.
record ID / 見出し番号the record's own number (084044) and the number shared by a headword's spelling variants (80089). TUFS uses the record ID, unpadded, as its cid.
code分類番号-段落-小段落-語番号, e.g. 2.3520-01-01-02; records in the same 小段落 are close synonyms.
見出し本体the headword proper, before the reading hint in （）and the usage note in ［］: 時 from 時（とき）. The dev set's lemma.
polite formthe ます form TUFS lists verbs under (会います); WLSP and wnja use the dictionary form (会う).
synseta set of synonyms with one meaning, named by its Princeton 3.0 offset: 02428924-v "gather in one place", in wnja wnja-02428924-v.
senseone word in one synset: wnja-00604617-a-12574 is 便利 as "convenient". The dev set links a WLSP record to a sense, not just a synset.
formsthe strings a wnja word lists besides its lemma, usually its katakana and hiragana readings: ['便利', 'ベンリ', 'べんり'].
ILIInterlingual Index ID (i3356), the language-neutral concept number a synset carries; empty for TUFS-only synsets such as 90000500-n.
