Background

The project links two inventories of Japanese word meanings. The Japanese WordNet (wnja 2.1) groups words into synsets, sets of synonyms with one definition. The 分類語彙表 (WLSP, Word List by Semantic Principles) is a thesaurus: every headword occurrence is a record filed at a position in a hierarchy. The same written word can be a member of several synsets and can have several WLSP records, so the question is which pairs of (wnja sense, WLSP record) mean the same thing.

A wnja sense and its synset

The word 多分 "probably" is sense wnja-00154449-r-1920 of synset wnja-00154449-r, whose Japanese members are 恐らく, 多分, うわさによれば, 想定されているところでは, 称されるところによれば and whose definition is そうであると信じられている、または評判である ("believed or reputed to be so"). The other four members are the synset context this script uses: four extra words that pin down which 多分 is meant.

Record 95548 is 多分 the adverb "probably", among other hedges; record 12382 is 多分 the noun "a large amount", among words for quantity. For the sense above, the dev set says 95548 is right. The three group levels are read directly from the code: 1.1910 is the 分類項目, -05 the 段落 within it, -02 the 小段落 within that. Across the whole database there are 96,051 senses (見出し番号) in 32,195 小段落, 9,909 段落 and 895 分類項目.

The candidate table

candidates.py has already paired each wnja sense with every WLSP record whose written form matches: 168,540 pairs in build/candidates.parquet. For 多分 there are two rows, one per record; the script adds nine columns to each.

chiVe: words as 300 numbers

chiVe (Works Applications, Apache 2.0) is a word2vec model trained on Japanese web text that was tokenised and normalised with Sudachi. The chive-1.3-mc30 release keeps every word seen at least 30 times: 759,011 words, each a vector of 300 floats (kv.vector_size). Words used in similar contexts get similar vectors, and cosine similarity (the dot product of two unit vectors, 1 for identical, near 0 for unrelated) measures that. The nearest neighbours of our two example words:

The 寝る list is what one hopes for: sleep words. The 多分 list shows the limits: 恐らく "probably" is there at 0.797, but so are まあ, けれど, な, てる, conversational particles that merely co-occur with hedges in web text. Word vectors capture distribution, not meaning, and the features inherit that.

Out of vocabulary: the Sudachi fallback

Many wnja lemmas are not chiVe words. Of the 40,753 distinct lemmas in the candidate table, 29,170 are in the vocabulary directly, 10,407 are not but can be tokenised by Sudachi (SplitMode.C, the longest units) into pieces that are, and 1,176 yield nothing. Three real cases:

選りだす選る · 出す 選る 0.842, 出す 0.725, もる 0.566: usable
さすが流石 one token; Sudachi's normalised form is the kanji spelling chiVe knows

So the fallback rescues spelling variants (交ざる → 混ざる, ズレ → ずれ) and compounds, and produces a noisy vector for a phrase. The same lookup serves WLSP headwords: 93,166 of the 96,051 senses get a vector.

Intuition

A WLSP record is defined by the company it keeps. If 多分 belongs at record 95548, then its vector should sit close to the vectors of どうやら, 恐らく, 確か; if it belongs at 12382, close to 多量, 大量, 膨大. The script measures both and leaves the comparison to the scorer. It does this twice: once with the word's own vector, once with the centroid of the other synset members, so that a sense with a clear synset gets evidence even when the word itself is ambiguous.

Two things to notice. chive_syn_sub_max is exactly 1.0 for the gold row because 恐らく is both a member of the synset and a headword in the 小段落: the same chiVe vector on both sides. That happens often: 242 of the 477 gold dev rows with this feature have it at 1.0, so the feature partly restates the structural overlap counts that candidates.py already computes. And the syn_* cosines separate the rows less sharply (0.79 vs 0.57) than the word's own (0.80 vs 0.24): the centroid of 恐らく and three particle-heavy phrases is a blurrier probe than 多分 itself.

When the vectors point the wrong way

Cosines measure topical closeness, and WLSP sometimes files the same word under a finer distinction than that. 寝る in synset wnja-00017865-v (寝る, 就寝, 就床, 床に就く: 睡眠の準備を整える, "go to bed") has three WLSP records:

Every chiVe feature prefers the 睡眠 record (its 段落 holds 寝過ぎる 0.883, 寝忘れる 0.860), while the dev set, via TUFS, points at the posture record 立ち居 "lying down". Whether the gold is the better reading is a separate question; the point is that these columns are evidence for a scorer, not a decision. In score.py they join the structural overlaps, and on the dev set top-1 strict accuracy went from 0.696 to 0.733 when they were added (README).

Coverage

Of the 168,540 rows, 165,241 have chive_has = 1 and 3,299 have 0 (1,176 distinct lemmas, such as 艨艟, 鈍物, 聞きすごす). The other columns are null more often: chive_sub_max is null in 11,957 rows (no vector for the word, or no other 小段落 headword with one), chive_para_max in 4,056, and the chive_syn_* columns in about 25,800 rows, where the synset has no other member with a vector.

2 · One vector per word, with the fallback

features_chive.py:59–102

Vectors.get is the only place a string becomes numbers. It checks a cache first, then the vocabulary, then asks Sudachi to split the word and averages the pieces it knows. Every vector is scaled to unit length by _unit (lines 74–76), which is what lets a later dot product be a cosine. Three counters record which path each distinct word took.

if word in self.kv:
    vec = self._unit(self.kv[word])
    self.n_direct += 1
elif self.tokenizer is not None:
    toks = [m.normalized_form() for m in self.tokenizer.tokenize(word, SplitMode.C)]
    parts = [self.kv[t] for t in toks if t in self.kv]
    if parts:
        vec = self._unit(np.mean(parts, axis=0))
        self.n_split += 1
if vec is None:
    self.n_missing += 1
self.cache[word] = vec

Three words through it: 多分 is in kv, so n_direct ticks. 選りだす is not; Sudachi returns 選る, 出す, both known, so their raw vectors are averaged, normalised, and n_split ticks. 追考 is not in kv and Sudachi returns it unsplit, so parts is empty, None is cached and n_missing ticks. Note the mean is taken over raw vectors, not unit ones, so a frequent token with a long vector weighs more. With --no-sudachi the tokenizer is None and the elif never runs.

3 · Centroids and matrices

features_chive.py:105–130

Two helpers over lists of unit vectors. centroid averages and renormalises (or returns None for an empty list); stack turns the list into a 2-d array so a whole neighbour set can be dotted with one vector in a single @.

def centroid(vecs: list[np.ndarray]) -> np.ndarray | None:
    if not vecs:
        return None
    m = np.mean(vecs, axis=0)
    n = np.linalg.norm(m)
    return m / n if n else m

def stack(vecs: list[np.ndarray]) -> np.ndarray | None:
    return np.vstack(vecs) if vecs else None

4 · Vectors for every WLSP group

features_chive.py:133–181

GroupVectors is built once. For each of the 96,051 WLSP senses it looks up the headword (rec.lemma, wlsp.py:72) and, if that has no vector, each of the sense's folded written forms (db.forms) until one hits. Then for each level it keeps, per group key, the member senses that have a vector and the centroid of their vectors. The group keys come from wlsp.py: the 小段落 key is the (分類番号, 段落, 小段落) triple (wlsp.py:97).

for level in ("subpara", "para", "item"):
    members = defaultdict(list)
    for key, mids in db.groups[level].items():
        members[key] = [m for m in mids if self.sense_vec[m] is not None]
    self.members[level] = dict(members)
    self.centroids[level] = {
        key: centroid([self.sense_vec[m] for m in mids]) for key, mids in members.items()
    }

Two accessors read it back. neighbour_matrix(mid, level) (lines 164–176) stacks the vectors of the other senses in mid's group, excluding mid itself: for record 95548 at "subpara" that is a 5 × 300 matrix for どうやら, 恐らく, 大方, 確か, 大概. group_centroid(mid, level) (lines 178–181) returns the group's centroid, which does include mid's own vector: the 分類項目 centroid for 95548 averages all 74 senses of 判断, 多分 among them.

5 · The eight numbers for one pair

features_chive.py:184–223

pair_features starts from a dict of eight Nones and fills what it can. The word half needs word_vec and a non-empty neighbour matrix; the synset half needs at least one other member with a vector. Either half can be missing independently, which is why the columns have different null counts.

sub = groups.neighbour_matrix(mid, "subpara")
para = groups.neighbour_matrix(mid, "para")
if word_vec is not None:
    if sub is not None:
        sims = sub @ word_vec
        out["chive_sub_max"], out["chive_sub_mean"] = float(sims.max()), float(sims.mean())
    if para is not None:
        sims = para @ word_vec
        out["chive_para_max"], out["chive_para_mean"] = float(sims.max()), float(sims.mean())
syn = centroid(syn_vecs)
if syn is not None:
    if sub is not None:
        out["chive_syn_sub_max"] = float((sub @ np.vstack(syn_vecs).T).max())
    for level, name in (
        ("subpara", "chive_syn_sub"),
        ("para", "chive_syn_para"),
        ("item", "chive_syn_item"),
    ):
        c = groups.group_centroid(mid, level)
        if c is not None:
            out[name] = float(c @ syn)

For 多分 and 95548: sub @ word_vec is the five cosines in the Intuition table, so sims.max() = 0.797 and sims.mean() = 0.640. sub @ np.vstack(syn_vecs).T is a 5 × 4 matrix of every (neighbour, synset member) cosine; its maximum is the 恐らく–恐らく cell, 1.0. The last loop dots the synset centroid with the three group centroids: 0.788, 0.802, 0.892.

6 · Every row of the table

add_features builds the group vectors, logs how many WLSP senses got one, then walks every wnja synset once and keeps, per synset, a dict from lemma to vector (lines 246–253). That walk is where the direct/split/missing counters fill up. The main loop pulls three columns from the table and, for each row, drops the row's own lemma from its synset dict before calling pair_features:
