Background

The project links two Japanese sense inventories. The Japanese WordNet (wnja:2.1, 67,509 synsets) groups words into synsets with a definition and examples. A wnja sense is one word in one synset, with an id such as wnja-02902079-n-33654: the word 鍔 in synset wnja-02902079-n, glossed 王冠から外側に突き出した円形の縁 (the brim of a hat). The 分類語彙表 (WLSP, ver 1.0.1, 101,067 records, 96,051 headword senses) is a thesaurus: a sense is a headword at a position, named by a 見出し番号 and a code 類.部門中項目分類項目-段落-小段落-語番号. The same written form つば has three positions:

見出し番号codelabels小段落 neighboursmeaning
481801.4250-15-01-01 体/生産物/衣料/帽子・マスクなどnone (alone in its 小段落 and 段落) hat brim
526641.4550-10-01-05 体/生産物/道具/刃物刀身、中子、さや sword guard
631191.5607-10-01-01 体/自然/身体/体液・分泌物つばき、生つば、唾液 saliva

The category path and the neighbours are what define a WLSP sense; the headword alone does not. That sentence is in the system prompt almost word for word (judge_claude.py:68–69).

The candidate table and its scorer

Earlier steps of the pipeline (candidates.py, score.py) pair every wnja sense with the WLSP senses whose written form matches and give each pair a probability p. The current build/scored.parquet has 168,540 pairs for 96,223 wnja senses and 40,753 words. For 鍔 the scorer wrote:

wnja senseWLSP 見出し番号codepevidence
wnja-02902079-n-33654481801.4250-15-01-010.823lemma
wnja-02902079-n-33654526641.4550-10-01-050.522lemma

The only evidence is that the lemma matches; nothing in the synset neighbourhood overlaps either category, so the scorer leans on priors. 0.522 is a shrug. Three kinds of shrug recur in the table, and the judge exists for them:

  • A pair in the band 0.3 to 0.7, like the 0.522 above. 23,059 pairs (13.7%) sit there, spread over 7,861 words: 鍔, 可能 (eight of its twelve pairs), 呼吸, 按摩.
  • A close top two. A sense whose best and second-best candidates are within 0.15 of each other, even if both are high. 黄色 has several senses scored 0.912 against both positions 1.5020-10-04-02 and -03 (adjacent entries in the same 小段落): the scorer cannot tell them apart, and probably should link both. 7,511 senses in 4,170 words are undecided this way. Contrast 父: best 0.98 (親・先祖), second 0.006 (輸入品, a reading match), a gap of 0.974, so no judge is needed.
  • A lone candidate. 60,426 pairs (36%) are the only candidate of their sense, in 28,638 words. Their median p is 0.934 and only 583 fall below 0.5, not because they are right but because the dev set has no negatives of that kind: every dev word was linked. 卸す (one sense, one WLSP position, 0.922) is the typical case. The scorer cannot learn to reject these, so --single-sample N sends a random N of them to the judge to measure how often they are wrong.

What the judge is asked for

Not a yes or no per pair. For one headword Claude sees all its wnja senses (labelled W1, W2, …) and all its WLSP senses (B1, B2, …) and returns the pairs that hold, each with one of four relations and a confidence (judge_claude.py:51, :60–67):

relationmeaningeffect in --apply
samesame meaningjudge_same = 1
narrowerthe WordNet sense is more specific than the WLSP sensejudge_same = 0, but judge_rel keeps the relation and judge_conf the confidence
broadermore general
relatedclearly connected, neither covers the other
(not listed)the pair does not holdjudge_same = 0, judge_rel = none, judge_conf = 0.0

The answer is forced into JSON by the API's structured-output format (OUTPUT_SCHEMA, judge_claude.py:72–93): an array of {wordnet, wlsp, relation, confidence} objects plus a note. The script never parses free text.

Where the judge sits

The README calls this tier 2b. Tier 1 (chiVe word vectors) and tier 2 (sentence embeddings) add feature columns; tier 2b adds labels from a model that can read the definitions; tier 3 (岩波国語辞典 definitions, via data/wlsp2iwanami) would enrich the judge's prompt when build/iwanami_defs.tsv exists. On this machine it does not, so the dry-run prompts carry no 岩波 lines.

What an answer looks like

Illustrative, not a model answer. A verdict that fits OUTPUT_SCHEMA for the prompt above might be:

Three states, and the distinction matters for the scorer: a judged pair the judge left out is a negative (0 / none / 0.0); a pair of a word that was never judged is unknown (null). 卸す was not selected by today's rule, so it stays null.

1 · Constants: the system prompt and the schema

RELATIONS is the closed set of four relation names; the same tuple feeds the JSON schema's enum and the validity check in parse_verdict. SYSTEM is the lexicographer persona. OUTPUT_SCHEMA is a JSON schema with additionalProperties: False at both levels and both links and note required, so the model cannot add or omit fields.

2 · WordCase: one word, rendered and hashed

judge_claude.py:96–120

A dataclass holding the lemma, the labelled senses and WLSP entries, and after finish() the prompt text, a 16-hex-digit key, and the label map pairs from (W_i, B_j) to (sense_id, midashi_no).

self.prompt = "\n".join(lines)
self.key = hashlib.sha256((SYSTEM + self.prompt).encode("utf-8")).hexdigest()[:16]
self.pairs = {
    (s["label"], w["label"]): (s["sense_id"], w["midashi_no"])
    for s in self.senses
    for w in self.wlsp
}

The key hashes the system prompt and the user prompt together, so editing SYSTEM, adding Iwanami definitions, or a changed synset gloss all produce a new key and a fresh request; the model name is not in the key, so a verdict from one model is reused when you switch --model. For 鍔 the recomputed key matches the file: ac71bd85ecc291e4.

3 · select_words: band, margin, sample

judge_claude.py:153–198 
band = df.filter((pl.col("p") >= low) & (pl.col("p") <= high))["lemma"]
ranked = (
    df.sort(["sense_id", "p"], descending=[False, True])
    .with_columns(pl.int_range(pl.len()).over("sense_id").alias("rank"))
    .filter(pl.col("rank") < 2)
    .group_by("sense_id")
    .agg(pl.col("p").max() - pl.col("p").min(), pl.len().alias("n"), pl.col("lemma").first())
    .filter((pl.col("n") == 2) & (pl.col("p") < margin))["lemma"]
)
chosen = set(band.to_list()) | set(ranked.to_list())

Line 179 is the band: any pair of the word with low ≤ p ≤ high, inclusive. Lines 180–187 rank each sense's candidates by p, keep the top two, and keep senses that have two (n == 2, so lone candidates never qualify here) whose gap is under margin. The aggregated max − min keeps the column name p, which is why the last filter reads pl.col("p") < margin. Lines 189–197 add the random lone-candidate sample: words whose largest n_cands is 1 (every sense has exactly one candidate), sampled with random.Random(seed) so the same N gives the same words. The result is sorted, so --max-words 20 takes the first twenty lemmas in code-point order, not a random twenty.

4 · build_cases: sense texts and WLSP texts

judge_claude.py:201–258

From the candidate rows of the chosen words it collects, per lemma, the set of sense_id → synset_id and the set of 見出し番号. Senses are labelled in sorted sense_id order, WLSP entries in order of their code. Each wnja sense becomes members, definition, up to two examples and an optional English gloss (:236–243); each WLSP sense becomes code, labels, headword, neighbours and optional 岩波 definitions (:244–255).

if ss.examples():
    text += f" 例: {' / '.join(ss.examples()[:2])}"
...
text = f"[{rec.code}] {rec.labels}: {rec.lemma}"
sub_n = "、".join(db.neighbours(rec, "subpara"))
para_n = "、".join(db.neighbours(rec, "para", 15))

db.neighbours (wlsp.py) lists the other headwords in the same group, excluding the record itself, so 52664 shows 刀身、中子、さや and 48180 shows nothing. The English gloss is only added with --en-gloss, which looks the synset up in omw-en:1.4 by ILI (main, :558–563); the dry run did not use it.

5 · read_iwanami: tier 3 definitions, if present

judge_claude.py:123–150

Reads build/iwanami_defs.tsv (sense id, definition) and NINJAL's WLSP2iwanami.txt (Shift_JIS; column 3 is a quoted CSV string whose first field is the WLSP record id), and returns definitions per record id. If either file is missing it returns {} and the prompts simply lack the 岩波 lines, which is the state on this machine.

A link naming a label that does not exist for this word (W9 for 鍔) or a relation outside the four is dropped silently; the test tests/test_judge_claude.py covers exactly that. Confidence is coerced with float() and defaults to 0.0.

8 · The cache: load_cache, append_cache

judge_claude.py:312–340

build/judge.jsonl is append-only, one JSON object per line with at least key, lemma, links. Loading builds a dict by key, so a later line with the same key wins. main computes todo = [c for c in cases if c.key not in cache] (:569) before any mode runs, which is what makes re-runs cheap.

Two details of the sync path. The request goes through the beta client with the server-side fallback (:362–364): if the safety classifiers decline, the API re-runs the request on a fallback model inside the same call. A refusal that survives that is skipped with a warning (:371–373), and a rate limit is retried once after sixty seconds (:365–370).

message = client.beta.messages.create(
    betas=["server-side-fallback-2026-07-01"], fallbacks="default", **params
)

The batch path uses the plain client and no fallback (the Batches API does not take it). Because batch results arrive later and in any order, run_submit stores each case's label map in judge_batches.json, keyed by the prompt hash as custom_id. run_collect rebuilds a bare WordCase from that map (:452–453), so it needs neither the wordnet nor the WLSP database; main returns before loading them (:546–548).

10 · apply_verdicts: three columns

judge_claude.py:469–506 
r, c = verdict.get((sense_id, mid), ("none", 0.0))
same.append(int(r == "same")), rel.append(r), conf.append(c if r != "none" else 0.0)
...
df = df.drop([c for c in df.columns if c.startswith("judge_")])
return df.with_columns(
    pl.Series("judge_same", same, dtype=pl.Int8),
    pl.Series("judge_rel", rel, dtype=pl.Utf8),
    pl.Series("judge_conf", conf, dtype=pl.Float32),
)

It walks the candidate table once: a word whose case key is in the cache is judged; each of its pairs gets the stored relation or none; everything else stays null. Existing judge_* columns are dropped first so the step is idempotent. A link the judge returns for a W×B pair that was never a candidate row (the prompt crosses all senses with all WLSP senses) is kept in the cache but has no row to land on. Note that --apply reads build/candidates.parquet (:573–575), not the scored table it selected from, so the columns go back upstream of score.py.
