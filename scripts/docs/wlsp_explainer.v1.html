Background

The 分類語彙表 (Bunrui Goihyō, "Word List by Semantic Principles", WLSP) is a Japanese thesaurus from the National Institute for Japanese Language and Linguistics (NINJAL). The 2004 増補改訂版 is distributed as one CSV file, bunruidb.txt, in Shift_JIS, with one record per headword occurrence. The project clones it into data/WLSP from masayu-a/WLSP; the version loaded here is ver 1.0.1. The same headword can occur in several places, and each place is a sense: the verb 会う "meet" is listed under 合体・出会い・集合など "joining, encountering, gathering" and again under 応接・送迎 "receiving and seeing off". The project's job is to map Japanese WordNet (wnja 2.1) senses onto those WLSP senses, and wlsp.py is the loader every other script reaches for.

Record types: A, B and the numbered children

The printed thesaurus lists some headwords with several spellings or readings on one line: あう（会・遭）, 市立（しりつ・いちりつ）. The database keeps that line as a type B record and adds one child record per variant, typed 1, 2, … in order. The children share the parent's 見出し番号 but get their own record ID and 語番号. A headword with no variants is a type A record on its own. wlsp.py calls a 見出し番号 a sense (wlsp.py:3–8): the A or B record is its canonical entry and the children only add written forms and readings.

$ iconv -f shift_jis -t utf-8 data/WLSP/bunruidb.txt | grep '^08404[345],'
084043,80089,B,用,活動,交わり,応接・送迎,2.3520,01,01,01,あう（会・遭）,あう,あう,うあ
084044,80089,1,用,活動,交わり,応接・送迎,2.3520,01,01,02,会う,会う,あう,うあ
084045,80089,2,用,活動,交わり,応接・送迎,2.3520,01,01,03,遭う,遭う,あう,うあ

So 見出し番号 80089 is one sense with three written forms (あう, 会う, 遭う) and one reading. Compare 市立, where the split is by reading instead: records 001956–001958 are B 市立（しりつ・いちりつ）, 1 市立（しりつ）, 2 市立（いちりつ）, giving sense 01848 one form and the readings しりつ, いちりつ and, from the parent row, the joined string しりつ・いちりつ. The 類 labels are grammatical only loosely: 体 is nouns, 用 verbs (する-verbs included: 遭遇する, 再会する), 相 adjectives, adjectival nouns and adverbs (この, こんな), and 他 the rest, conjunctions and interjections (及び, おーしーつくつく, the last record in the file, under 動物の鳴き声). Only the four digits 1–4 occur, so the "x" fallback in pos never fires on this data. The 他 class has no 部門 name, which is why its labels read 他//接続/累加, with an empty slot.

Below the 分類項目, the 2004 database adds three numbers the printed book only implied by layout. Records in the same 小段落 are close synonyms; the same 段落 groups related senses; the 語番号 orders words within the 小段落 (wlsp.py:10–13). The surprise in this tree is that the 語番号 are not dense: in 小段落 2.3520-01-01 the parent あう is word 01 and 会わせる・会わす is word 04, because 02 and 03 went to the children 会う and 遭う. Children take 語番号 but are not senses.

240 senses that are not words. The file also carries records whose headword is ＊, one per semantic break inside a 分類項目 (kaisetsu.txt calls them 意味的区切りを示すレコード). They are type A, always 小段落 and 語番号 99, and load() counts them as senses like any other A record. After folding, ＊ becomes the ASCII *, so db.by_form["*"] holds 240 見出し番号, the most ambiguous "form" in the index. Nothing in wlsp.py filters them.

Headword notation: 見出し and 見出し本体

The midashi column carries two kinds of annotation in full-width brackets. Round brackets give a reading or spelling hint: 者（もの）, あう（会・遭）. Square brackets give a usage note with 〜 standing for the headword: −こ［椀〜］ "-ko as in 椀こ", 変［本能寺の〜］ "the 変 of 本能寺", 迫真［〜の演技］, 生（なま）［〜の声］ with both. In this file 8,016 records have a round-bracket hint and 1,531 a square-bracket note (204 have both); 9,343 records differ between midashi and midashi_hontai, and the remaining 91,724 are identical in both. The 本体 column already has the brackets removed by NINJAL, so what normalise_midashi strips in practice is the midashi column (wlsp.py:102–111):

>>> [normalise_midashi(m) for m in ("者（もの）", "−こ［椀〜］", "あう（会・遭）", "市立（しりつ・いちりつ）", "生（なま）［〜の声］")]
['者', '−こ', 'あう', '市立', '生']
>>> sum(1 for r in db.records.values() if r.midashi_hontai != r.lemma)
0

That last line is worth a pause: WlspEntry.lemma applies the stripper to midashi_hontai, and on this file that changes nothing. The property is insurance, and the place the function does real work is wherever a caller feeds it a raw midashi. One wart is visible in the examples: a headword with two hints, 何（なに）か・何（なん）か, normalises to 何か・何か.

Intuition

Three ideas carry the module. A record is one line of the file; a sense is a 見出し番号, which gathers a parent record and its children; and a sense's neighbourhood is everything that shares a prefix of its code. The loader builds indices in both directions: from a written form or reading to the senses that carry it, and from a sense to the senses around it.

Notice that 出会う, 遭遇する and 出くわす appear on both sides: WLSP lists the same headword in both categories, each time as its own sense. Forms fold, readings do not

Matching a wnja lemma to a WLSP headword has to survive the usual Japanese spelling variation. fold applies Unicode NFKC and then turns katakana into hiragana, so a lookup is script-blind for kana and width-blind for the Latin letters WLSP writes in full width (941 lemmas change under NFKC: Ａ級 → A級, ＊ → *). The fold is deliberate and blunt. It lets トラブる find トラブル, and it also makes これら "these" share an entry with コレラ "cholera" and まま "as is" with ママ "mum": 54 folded forms merge headwords that differ only in script. What it does not do is inflect (会います finds nothing) or match readings (珈琲 is not a WLSP spelling, and lookup is a written-form lookup only; readings live in by_yomi, which callers consult themselves, see the lookup step). Readings are kept exactly as written, including the parent's joined form しりつ・いちりつ.

Code

Nine parts, in the order a caller meets them: constants, the record class, two string normalisers, the CSV reader, the index builder, and four query methods.

1 · The contract, in the docstring

wlsp.py:1–14

The module docstring states the two decisions everything else follows: a sense is a 見出し番号 with its A or B record as canonical entry, and position is the 分類番号 plus 段落, 小段落 and 語番号, with 小段落 meaning close synonyms and 段落 meaning related senses.

2 · Constants

wlsp.py:26–47

WLSP_FIELDS names the fifteen columns in file order; RUI_TO_POS turns the 類 digit into a wordnet part of speech; _BRACKETS matches the four bracket styles a headword may carry.

RUI_TO_POS = {"1": "n", "2": "v", "3": "a", "4": "r"}

_BRACKETS = re.compile(r"（[^）]*）|\[[^\]]*\]|［[^］]*］|〔[^〕]*〕")

Of the four alternatives, only full-width （） (8,016 records) and ［］ (1,531) occur in bunruidb.txt; the ASCII [] and 〔〕 branches never match on this data.

3 · WlspEntry: one record and its keys

wlsp.py:50–99

A frozen dataclass with the eleven fields the project needs (the four label columns are pre-joined into labels; 逆読み is dropped). Its properties derive the position code, the bare lemma, the part of speech, and the four group keys, each a prefix of the code:

@property
def code(self) -> str:
    """Full WLSP position code, e.g. ``2.3520-01-01-02``."""
    return f"{self.bunrui_no}-{self.danraku}-{self.shodanraku}-{self.go_no}"

@property
def middle_key(self) -> str:
    """Key of the 中項目 group (類.部門中項目), e.g. ``2.35``."""
    return self.bunrui_no[:4]

@property
def subpara_key(self) -> tuple[str, str, str]:
    """Key of the 小段落 group."""
    return (self.bunrui_no, self.danraku, self.shodanraku)

For record 084043 these give:

>>> r = db.senses["80089"]
>>> r.code, r.lemma, r.pos
('2.3520-01-01-01', 'あう', 'v')
>>> r.middle_key, r.item_key, r.para_key, r.subpara_key
('2.35', '2.3520', ('2.3520', '01'), ('2.3520', '01', '01'))

item_key is the whole bunrui_no (line 84) and middle_key its first four characters, 2.35 (line 89): the point counts, so four characters is one digit of 類 and two of 部門中項目.

4 · normalise_midashi

wlsp.py:102–111 
def normalise_midashi(midashi: str) -> str:
    return _BRACKETS.sub("", midashi).strip()

Delete every bracketed span, then trim. 生（なま）［〜の声］ loses both annotations and becomes 生; あう（会・遭） becomes あう, so the kanji variants in the hint are not recovered here (they come from the child records instead). Nothing inside the brackets is used.

5 · Kana folding

wlsp.py:114–147 
def hira_to_kata(text: str) -> str:
    return "".join(chr(ord(c) + 0x60) if "ぁ" <= c <= "ゖ" else c for c in text)

def kata_to_hira(text: str) -> str:
    return "".join(chr(ord(c) - 0x60) if "ァ" <= c <= "ヶ" else c for c in text)

def fold(text: str) -> str:
    return kata_to_hira(unicodedata.normalize("NFKC", text))

Hiragana and katakana sit 0x60 apart in Unicode (あ U+3042, ア U+30A2), so a shift of the code point converts the script. The ranges ぁ–ゖ and ァ–ヶ cover the small kana and the ヵ ヶ counters but leave the long-vowel mark ー alone, which is why fold("コーヒー") is こーひー and not the WLSP reading こおひい. NFKC runs first so that half-width ｺｰﾋｰ becomes full-width katakana before the shift. hira_to_kata is not used inside this module; build_devset.py imports it.

Two loops. The first walks every record, keeps the A and B records as the canonical entry of their 見出し番号, and pools the folded lemma and the reading of every record, children included, under that 見出し番号:

For 見出し番号 80089, the three records 084043, 084044, 084045 run through this loop in turn: the B record becomes senses["80089"], and the set forms["80089"] grows to {あう, 会う, 遭う} while readings["80089"] stays {あう}. The second loop walks the senses and inverts those sets, and files each sense under its part of speech and its four group keys:
